# GeniaPassword 2.1.1 Final

Локальный портативный менеджер паролей для Windows. Без аккаунтов, сервера и обязательного интернета: приложение работает из своей папки и хранит зашифрованное хранилище рядом с EXE.

После первых сохранений portable-папка имеет вид:

```text
GeniaPassword.exe
vault.pnb
vault.pnb.bak
backups\
  vault_YYYYMMDD_HHMMSS_mmm_revN.pnb
```

Папка `backups` содержит до 10 последних зашифрованных копий. Перед заменой рабочего vault новая резервная копия проверяется по SHA-256.

Во время атомарного сохранения может кратковременно появляться `vault.pnb.tmp`; после завершения он удаляется.


## Финальная полировка 2.1.1

- Поиск поддерживает несколько слов: каждое слово должно находиться хотя бы в одном из полей записи.
- Горячие клавиши главного окна: `Ctrl+F` — поиск, `Ctrl+N` — новая запись, `Ctrl+L` — блокировка, `Esc` — очистить активный поиск.
- В «Управлении» явно показаны политика автоблокировки, очистка буфера и офлайн-режим.
- Добавлена кнопка открытия локальной папки проверенных резервных копий.
- Криптографическое ядро и формат Vault v2 не менялись.

## Основные возможности

- название, сайт, логин, пароль и многострочные заметки;
- до 100 дополнительных полей на запись, включая секретные поля;
- защита от повторяющихся и зарезервированных названий дополнительных полей;
- настраиваемый локальный генератор паролей: длина 8–64, заглавные, цифры, спецсимволы и исключение похожих O/0, l/1; существующий пароль заменяется только после отдельного подтверждения;
- переключатель «Показать / Скрыть»;
- история до 5 предыдущих паролей записи внутри зашифрованного vault;
- поиск по названию, сайту, логину, заметкам и дополнительным полям;
- локальный аудит: повторяющиеся, короткие и очевидные пароли, HTTP-адреса и информационный сигнал о давно не менявшихся паролях;
- копирование секретов с очисткой буфера через 30 секунд;
- защита копирования: секрет помещается в Clipboard с флагом исключения из Windows Clipboard History / Cloud Clipboard;
- приложение не хранит вторую строковую копию скопированного пароля для таймера очистки — используется номер изменения системного Clipboard;
- Ctrl+C из раскрытых секретных полей отключён, чтобы нельзя было обойти защищённый путь копирования;
- ручная блокировка, автоблокировка после 5 минут бездействия, блокировка при `Win+L`, отключении сессии и переходе Windows в сон;
- смена мастер-пароля из интерфейса;
- безопасное удаление только полностью идентичных дублей;
- резервная копия `vault.pnb.bak` + ротация до 10 проверенных копий в `backups`;
- защита от тихой перезаписи: если `vault.pnb` изменился извне после разблокировки (например, заменён файлом с Android), сохранение блокируется до повторного открытия актуального vault;
- защита окон от обычного screen capture через `SetWindowDisplayAffinity` (это дополнительный слой, а не защита от администратора/вредоносного ПО).

## Защита vault v2

Формат v2 отделяет мастер-пароль от ключа, которым непосредственно зашифрованы записи:

1. При создании хранилища генерируется случайный 256-битный `VaultKey`.
2. Данные vault шифруются `VaultKey` с помощью AES-256-GCM.
3. Из мастер-пароля и случайной соли Argon2id формирует отдельный 256-битный unlock-key.
4. Unlock-key шифрует только `VaultKey` (AES-256-GCM).
5. Версия, KDF-параметры, соль, номер ревизии и время сохранения входят в authenticated associated data, поэтому их незаметная подмена приводит к ошибке аутентификации.

Текущие параметры нового/усиливаемого vault: Argon2id, 64 MiB памяти, 3 итерации, parallelism 2. Более старые v2-файлы с допустимым, но слабее текущего профилем после успешной разблокировки автоматически перепривязывают тот же `VaultKey` к новому `UnlockKey`; формат данных не меняется. Параметры записываются в заголовок vault и проходят жёсткую проверку границ перед запуском KDF, чтобы повреждённый файл не мог запросить произвольный объём памяти или вычислений.

Для Argon2id используется `TopSecret.Cryptography.Argon2` версии `2.2.0`. Это единственная внешняя NuGet-зависимость проекта; при первой сборке требуется доступ к NuGet для восстановления пакета. В single-file publish библиотека упаковывается внутрь `GeniaPassword.exe`.

Мастер-пароль для нового vault должен содержать не менее 8 символов. Специальные символы, цифры и регистр не являются обязательными. Для лучшей защиты рекомендуется 12–16+ символов или длинная уникальная парольная фраза. Очевидные/common-пароли и строка из одного повторяющегося символа отклоняются.

## Совместимость со старым vault v1

Старые `vault.pnb` формата v1 (PBKDF2-HMAC-SHA256, 600 000 итераций, AES-GCM) продолжают открываться.

После успешной разблокировки GeniaPassword автоматически пытается переписать основной файл в v2. При успешной миграции:

- `vault.pnb` становится v2;
- исходный v1 сохраняется как `vault.pnb.bak`;
- все записи, заметки и дополнительные поля сохраняются;
- для старых записей дата последней смены пароля инициализируется известной датой изменения записи.

Если автоматическая миграция не может записать файл (например, нет прав), открытые данные не блокируются: попытка обновления повторится при следующем сохранении.

## Смена мастер-пароля

В v2 смена мастер-пароля создаёт новую соль и новый Argon2id unlock-key. Сам случайный `VaultKey` остаётся тем же, после чего vault безопасно пересохраняется с новым мастер-паролем.

После успешной смены приложение также обновляет `vault.pnb.bak`, чтобы старая резервная копия не оставалась открываемой прежним мастер-паролем. Если обновить backup не удалось, приложение показывает отдельное предупреждение.

## Резервное копирование и восстановление

При первом успешном создании vault приложение сразу создаёт `vault.pnb` и `vault.pnb.bak`. При обычных последующих сохранениях `.bak` содержит предыдущую успешно сохранённую версию, а перед заменой дополнительно создаётся проверенная копия в `backups` (до 10 штук).

Если основной `vault.pnb` отсутствует, программа сначала ищет `vault.pnb.bak`, затем последние файлы из `backups` и предлагает восстановление. Любой восстановленный файл всё равно проходит обычную AES-GCM проверку при вводе мастер-пароля.

Для внешнего backup достаточно копировать всю portable-папку либо отдельно `vault.pnb` и `vault.pnb.bak` на другой носитель.

## Что защита не может гарантировать

Шифрование защищает закрытый файл vault. После разблокировки приложению необходимо иметь доступ к открытым данным, поэтому вредоносная программа с правами текущего пользователя, кейлоггер, дамп процесса или физический доступ к уже разблокированному компьютеру находятся вне возможностей одного файлового шифрования.

Ключевые byte-буферы, временный plaintext и промежуточные password-byte buffers по возможности зануляются через `CryptographicOperations.ZeroMemory`. Обычные .NET `string` являются immutable, поэтому гарантированно стереть каждую строковую копию пароля из managed heap невозможно. GeniaPassword старается не создавать лишних копий и блокирует/очищает состояние как можно раньше.

Это персональное приложение без независимого криптографического аудита. Для критически важных корпоративных, финансовых или инфраструктурных секретов используйте продукт с независимым аудитом и формальной моделью безопасности.

## Запуск из Visual Studio 2026

1. Установите workload **.NET desktop development** и .NET 10 SDK.
2. Откройте `GeniaPassword.sln`.
3. Разрешите NuGet восстановить `TopSecret.Cryptography.Argon2`.
4. Запустите проект (`F5`).

## Portable single-file publish

Самый простой способ — запустить `BUILD_PORTABLE.cmd` из корня исходников. При успешной публикации получится ровно один файл:

```text
dist\GeniaPassword-Portable\GeniaPassword.exe
```

Эквивалентная команда:

```powershell
dotnet publish .\PasswordNotebook\GeniaPassword.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true -p:PublishTrimmed=false -p:PublishReadyToRun=false -o .\dist\GeniaPassword-Portable
```

Не запускайте portable-копию из каталога, куда обычному пользователю запрещена запись (например, `Program Files`): приложению необходимо создавать и заменять `vault.pnb` рядом с EXE.

Перед передачей исходников не включайте `bin/`, `obj/`, `.vs/`, `dist/`, `*.user`, `vault.pnb`, `vault.pnb.bak`, `vault.pnb.tmp` и папку `backups/`.
